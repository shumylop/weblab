# Облікові записи WEB LAB

Сайт: https://shumylop.github.io/weblab/ · **Мій обліковий запис** у меню.

- Викладач входить у свій кабінет, створює логін, псевдонім та пароль учня (від 6 символів, без вимог до великих літер, цифр або спецсимволів), передає їх особисто.
- Самостійної реєстрації у WEB LAB немає. Вхід до Supabase Auth сам по собі не дає доступу: потрібен запис у захищеній таблиці облікових записів, який створює лише сервер від імені викладача.
- У списку **Мої учні** викладач бачить кількість і назви завершених уроків для кожного учня. Кнопка **Оновити** завантажує останній онлайн-прогрес. Учнівський код і проєкти в цей список не передаються.
- Панель викладача видає нові паролі та вимикає/вмикає доступ. Паролі не зберігаються в коді, SQL-таблицях застосунку чи JSON-експорті; їх обробляє Supabase Auth.
- Учень може змінити власний пароль. Внутрішні адреси виду `login@login.weblab.invalid` є технічними ідентифікаторами, а не справжньою поштою. Листи не надсилаються.
- Прогрес, код та проєкти автоматично зберігаються онлайн. При одночасній роботі на двох пристроях перевіряється версія запису: конфлікт не перезаписує дані мовчки. Для розв’язання експортуй свою копію та завантаж актуальний онлайн-прогрес.
- Онлайн-прогрес у браузері тримається в пам’яті; авторизаційний сеанс — у sessionStorage цієї вкладки. Виходь після роботи на спільному комп’ютері. Скопійовані вкладки можуть успадкувати sessionStorage; після виходу не залишай інші свої вкладки відкритими.
- Гостьові локальні профілі залишаються окремими. Щоб перенести попередню роботу, експортуй гостьовий JSON, увійди та імпортуй його: у твій обліковий запис переноситься лише активний профіль файлу. Імпорт не дає прав викладача.
- За відсутності інтернету зміни залишаються в пам’яті, показується попередження; не закривай вкладку, доки не відновиш зв’язок або не експортуєш JSON. Це не повноцінний офлайн-сайт.

## Розгортання авторизації

Проєкт Supabase: `cudpryhppcfmcxxfgkmh` (WEB LAB, організація shumylo, **Free**). Наявний проєкт «254» не використовується й не змінюється.

Публічний URL та **publishable** key розміщені в `src/config/cloud.json`; вони призначені для браузера. `service_role` є тільки в серверному середовищі Edge Function, його не можна додавати в GitHub або Vite. Конфіг можна перевизначити `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY`.

Таблиці та RLS описані в `supabase/setup/schema.sql`. Серверна функція — `supabase/functions/manage-students/index.ts`; вона перевіряє JWT через Auth, потім роль та активність викладача в таблиці. Клієнт не може змінювати роль або створювати облікові записи напряму. Function gateway `verify_jwt=false` потрібен для сучасного publishable key; власна перевірка токена у функції обов’язкова. CORS дозволяє тільки `https://shumylop.github.io`.

Першого викладача створено одноразовою захищеною ініціалізацією. Її секрет видалено, bootstrap-дії у поточній функції немає. Порожня службова таблиця `weblab_setup` недоступна браузерним ролям навмисно. Для нового окремого проєкту першого викладача має створити власник через Supabase Auth Admin API та призначити роль у таблиці; публічного маршруту самопризначення немає.

На Free можливе призупинення після неактивності; безплатний тариф має квоти, резервні JSON-копії варто робити регулярно. Платний тариф не підключений. GitHub Pages залишається статичним фронтендом; серверна частина працює в Supabase.

Перевірка бекенду: `scripts/verify-cloud.mjs` приймає JSON із паролем викладача через stdin без еха. Створює лише синтетичного `qa_`-учня з серверною позначкою тесту й видаляє його та прогрес у `finally`. Не виводить паролів. Перевіряє RLS, синхронізацію, конфлікти, зміну пароля та вимкнення доступу.

# WEB LAB — Веброзробка з нуля

Готовий локальний навчальний застосунок українською для учнів 8–9 класів. Учні створюють власний HTML/CSS-сайт і вчаться знаходити помилки у верстці. Гостьовий режим працює без реєстрації. Вхід за виданим викладачем логіном та онлайн-прогрес використовують окремий проєкт Supabase Free.

[План ігрових місій і майбутніх уроків](docs/learning-roadmap.md) — черга розвитку курсу для 8–9 класів.

## Запуск

Потрібен Node.js **22.12 або новіший** та npm.

```sh
npm install
npm run dev
```

Відкрий адресу `Local`, яку надрукує Vite. Якщо стандартний порт зайнятий, Vite обере інший; можна вказати його явно:

```sh
npm run dev -- --port 5187
```

Production-збірка й локальний перегляд:

```sh
npm run build
npm run preview
```

Команди потрібно виконувати в каталозі проєкту. Відкривати `index.html` подвійним кліком не потрібно: ES-модулі працюють через HTTP-сервер.

## Що реалізовано

- Головна з особистим прогресом і візуальний маршрут із семи відкритих модулів.
- П’ять етапів уроку: знайомство, експеримент, практика, мінітест, підсумок. Кожен триває приблизно 5–15 хвилин.
- Анімована модель HTTP-запиту, розбір та складання URL, живі демонстрації HTML, списків, CSS, Flexbox і тем сайту.
- HTML/CSS-редактор із Prism-підсвічуванням, автоматичним preview, запуском, скиданням, підказками та перевіркою практики. `Tab` додає два пробіли; `Shift+Tab` дозволяє вийти з редактора назад.
- DOM-перевірка HTML, CSSOM-перевірка правил, відповідність селекторів реальним елементам, основний каскад і специфічність, shorthand та мобільні правила.
- Місія «Афіша клубу» в модулі HTML: учень збирає афішу з блоків, бачить результат, а потім пише HTML для іншої події.
- Місія «Врятуй сайт на телефоні» в модулі Flexbox: учень передбачає перенесення карток, перевіряє макет на двох ширинах і виправляє інший макет у CSS.
- Місія «Баг-детектив»: учень порівнює афішу зі зразком, виправляє три помилки по черзі, а потім самостійно лагодить іншу картку.
- 35 запитань: один/кілька варіантів, правда/неправда, результат коду. Пояснення відкриваються лише після відповіді; повторення необмежені. Найкращий результат не погіршується. Прохідний результат — 60%.
- Досягнення, відмітки завершених модулів, відновлення поточного уроку й етапу.
- Власні ідеї: назва, аудиторія, тип, три кроки, окремий код і відмітка завершення. Експорт готового HTML із CSS.
- Локальні профілі для спільних комп’ютерів, резервні копії та перевірений імпорт JSON.
- Адаптивне меню, вкладки коду/результату на телефоні, клавіатурне керування, видимий focus, зменшення руху через `prefers-reduced-motion`.

## GitHub Pages: точні кроки

1. Створи порожній репозиторій `web-lab` на GitHub. Не додавай до нього README через інтерфейс, якщо завантажуєш цей проєкт з уже наявною історією Git.
2. У каталозі проєкту виконай (заміни `USERNAME` своїм логіном):

   ```sh
   git add .
   git commit -m 'Build WEB LAB learning platform'
   git branch -M main
   git remote add origin https://github.com/USERNAME/web-lab.git
   git push -u origin main
   ```

   Якщо `origin` уже існує, перевір `git remote -v` та за потреби використовуй `git remote set-url origin ...`.

3. У репозиторії відкрий **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Відкрий **Actions → Deploy WEB LAB to GitHub Pages**. Якщо перший запуск завершився до ввімкнення Pages, обери **Run workflow** на `main` або повтори невдалий запуск.
5. Після успішного `deploy` сайт доступний за `https://USERNAME.github.io/web-lab/`.

Workflow `.github/workflows/deploy.yml` автоматично запускається після push у `main`: `npm ci`, модульні тести, браузерні тести, TypeScript-перевірка та production build, завантаження `dist`, деплой у Pages. У `Settings → Actions → General` мають бути дозволені GitHub Actions. Деплой виконується штатним `GITHUB_TOKEN`, персональний токен не потрібен.

`VITE_BASE_PATH` задається автоматично за назвою репозиторію. Усі маршрути використовують hash: `/web-lab/#/lesson/2`; оновлення таких сторінок працює без серверного rewrite.

Локально перевірити збірку для вкладеного шляху:

```sh
VITE_BASE_PATH=/web-lab/ npm run build
VITE_BASE_PATH=/web-lab/ npm run preview
```

Відкрий `/web-lab/` на адресі preview-сервера. Для репозиторію `USERNAME.github.io` або власного домену зі встановленням у корінь зміни `VITE_BASE_PATH` у workflow на `/`.

**Репозиторій проєкту:** https://github.com/shumylop/weblab. Workflow публікує сайт після push до `main`. Адреса GitHub Pages після успішного деплою: https://shumylop.github.io/weblab/.

## Збереження та профілі

У `localStorage` під ключем `web-lab:v1` зберігається версійований JSON: активний профіль, уроки та етапи, виконані вправи, найкращі результати тестів, код, власні ідеї та бейджі. Автозбереження має debounce 450 мс; при приховуванні чи закритті вкладки зміни записуються одразу.

**Дані не синхронізуються між браузерами, пристроями й адресами сайту.** Після очищення даних сайту або завершення приватного сеансу вони можуть бути втрачені. Два локальні порти теж мають різні сховища. Якщо браузер блокує запис або закінчується квота, застосунок показує попередження; використовуй експорт перед закриттям.

У **Профілі та збереження** можна створити псевдонім і перемикати профілі, зокрема через меню у верхній панелі. Профілі ізолюють навчальний прогрес, але **не є захистом доступу**: будь-хто за цим комп’ютером може перемкнутися. Не записуй особисті дані. Максимум — 30 профілів та 100 ідей у профілі у форматі резервної копії.

### Експорт та імпорт

1. Відкрий **Профілі та збереження**.
2. **Експорт прогресу · JSON** завантажує всі локальні профілі разом із кодом.
3. Для перенесення відкрий WEB LAB в іншому браузері, обери **Імпорт прогресу** та цей JSON-файл.
4. Файл до 2 МБ перевіряється за схемою: версія, типи, ідентифікатори, діапазони результатів, етапи, структура коду та проєктів. Перед заміною всіх профілів потрібне підтвердження. Невірний файл нічого не змінює.
5. **Почати навчання заново** після підтвердження очищує тільки поточний профіль, включно з його кодом та ідеями. Інші профілі залишаються.

HTML-експорт у редакторі — готова сторінка, а не резервна копія прогресу. CSS вбудовується в `<style>`, надана ілюстрація — у data URL. Власні зовнішні картинки потребуватимуть доступу до їхніх адрес.

## Як додати урок

1. Створи `src/content/lessons/lesson-07.ts` за зразком сусідніх файлів і використай `satisfies Lesson` з `src/types/index.ts`.
2. Заповни `id`, `title`, `description`, `estimatedDuration`, `tag`, `color`, `objectives`, `theoryBlocks`, `interactiveExercises`, `quizQuestions`, `optionalChallenge`, `summary`, `references`.
3. У вправі додай унікальний `id`, інструкції, HTML/CSS-стартер, `validationRules`, підказки й повідомлення успіху. Правило може перевіряти DOM-селектор, кількість, текст, атрибут, CSS-властивість або адаптивність.
4. Імпортуй урок у `src/content/index.ts`. Спільні компоненти уроку, тесту й редактора змінювати не потрібно. Для нового спеціального інтерактиву додай компонент за аналогією з `ConceptDemo.vue`.
5. Кількість модулів, навігація й допустимі ID імпорту беруться з каталогу автоматично. Умови спеціальних досягнень можна доповнити в `features/storage.ts`. Перевір міграцію формату збереження, якщо змінюєш його структуру.
6. Додай позитивний і негативний тест перевірки вправи та запусти `npm run test` і `npm run build`.

Для звичайних HTML/CSS-уроків достатньо контентного файлу та реєстрації в каталозі. Уся теорія, вправи та запитання винесені з компонентів.

## Тести

```sh
npm run test
npx playwright install chromium
npm run test:e2e
npm run build

# Додаткова перевірка GitHub Pages project path:
VITE_BASE_PATH=/web-lab/ npm run build
npx playwright test --config=playwright.pages.config.ts
```

Playwright автоматично запускає dev-сервер на порту 5187 або використовує вже запущений локальний сервер; у CI сервер завжди окремий. У Linux CI для браузера застосовується `npx playwright install --with-deps chromium`.

Модульні тести перевіряють повноту контенту, DOM/CSS-валидацію, негативні приклади, каскад, адаптивні правила, відповіді, локальні профілі, схему імпорту й безпеку згенерованого документа. Браузерні сценарії охоплюють повне проходження уроку, всі практики, preview, reload, проєкти, експорт/імпорт, відмову сховища та мобільний вигляд. Скріншоти і trace при помилках записуються до ігнорованого `test-results/`.

## Архітектура та безпека

Vue 3 + TypeScript, Vite, Tailwind CSS 4, Lucide, Prism, Vitest, Playwright. Аналітики немає. Для облікових записів використовуються Supabase Auth, таблиці з RLS та серверна Edge Function. Учням достатньо псевдоніма; справжню пошту вводити не потрібно. Системні шрифти працюють без запитів до сторонніх сервісів.

```text
src/
  App.vue                   # оболонка, hash-маршрути та маршрут модулів
  components/               # уроки, демонстрації, редактор, тест, ідеї, налаштування
  content/lessons/           # навчальні модулі
  features/storage.ts       # профілі, debounce, імпорт, прогрес, досягнення
  features/validation.ts    # DOMParser та CSSOM
  features/preview.ts       # ізольований HTML і самодостатній експорт
  types/                    # інтерфейси контенту та даних
  styles/                   # дизайн-система й адаптивні стилі
```

Preview використовує `iframe sandbox=""` без дозволів. Учнівський HTML не вставляється в DOM застосунку. Додаткова CSP забороняє скрипти, вкладені документи, форми й завантаження зовнішніх стилів; дозволені вбудовані CSS та картинки `data:`/HTTPS. Видаляються скрипти, подієві атрибути, небезпечні URL, base, refresh, link та вкладені фрейми. Немає `eval` або `new Function`.

Перевірка CSS — навчальна, детермінована перевірка вибраних властивостей через CSSOM, не повний рушій розкладки. Вона підтримує правила для класів та тегів, inline-стилі, базову специфічність, `!important`, скорочений background/padding та мобільні media queries. Дуже складні селектори, CSS layers, обчислення layout чи нестандартні способи адаптивності можуть вимагати розширення валідатора. Візуальну якість остаточно оцінює учень у preview. Картки в уроках 5–6 використовують заданий контейнер `.cards`, але стилізувати його можна іншими селекторами, що збігаються з цим елементом.
